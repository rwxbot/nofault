# v0.6.0 架构：RPC 框架

## 一句话

**TCP 是字节流，没有消息边界**——所以自己分帧；
**一条连接上可以同时有多个在途调用**——所以每个请求要有 id。

这两条决定了 RPC 协议的全部设计。

## 一、协议：4 字节长度 + JSON

```
[ 4 字节大端长度 ][ JSON body ]
```

不分帧的后果是"偶发的 JSON 解析失败"，而且**只在负载稍大时才复现**。
长度前缀还顺带带来两个好处：读满整帧前就知道要分配多少内存，
以及可以挡住超大帧打爆内存（`maxFrameBytes`，超限直接丢缓冲并报错）。
